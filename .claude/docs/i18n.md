# Internationalization (i18n) — detailed mechanics

The site is trilingual: **English at `/`** (default, `content/`), **Spanish at `/es/`** (`content/es/`), **Japanese at `/ja/`** (`content/ja/`). Spanish and Japanese are neutral Latin American Spanish (formal `usted`) and です・ます polite register respectively. The ONLY content left in English by design is the **body** of tutorial posts (they stay stub cards linking to the English original).

For the compact "translate new content" rule, see `CLAUDE.md`. For the translation mechanism and glossary, use `/project:translate-content` and see `.claude/skills/translate-content/SKILL.md` + `.claude/skills/translate-content/references/{glossary,field-rules}.md`. Historical backfill/audit narration lives in `logs/` (search `logs/*i18n*` and `logs/*spanish*`/`logs/*japanese*`).

## Config & layout

- **Content layout:** `config/_default/config.yaml` `module.mounts` keep English in `content/` and Spanish/Japanese in `content/es/` and `content/ja/`, isolated via `excludeFiles: '{es,ja}/**'` on the en mount. English is NOT moved to `content/en/` (preserves all `content/tutorials/…`, `content/articles/…`, `content/presentations/…` conventions the skills depend on). When any `mounts` are defined, the default component mounts (assets/static/layouts/data/i18n/archetypes) MUST be re-declared — they are.
- **Languages/menu:** `config/_default/languages.yaml` (`en`, `es`, `ja`). The navbar globe switcher is enabled via `params.yaml` `main_menu.show_language: true` and appears only on translated pages. The Spanish and Japanese menus mirror the English nav (AboutMe, ResearchLab, Articles, Books, Courses, Presentations, Software, WebApps, Data, Tutorials, Events, Contact) with localized names; section items point to `/es/<section>/` and `/ja/<section>/`, homepage anchors stay `#…`.
- **Translated homepage:** `content/es/home/` and `content/ja/home/` mirror the active widgets of `content/home/`; bios from `content/<lang>/authors/admin/_index.md`. Dynamic widgets (featured/showcase/people) query the current language's `site.RegularPages`, so sub-pages under `content/<lang>/<section>/<slug>/` populate `/es/` and `/ja/` automatically. Per-language bundles need their own image copies (avatars, `featured.*`, gallery). Article/presentation/software `tags` stay English (they are query keys), as do the `filters:` option `value`s and the matching item params (`platform`, `region`, `topic`, `data_type`, `book_format`); only the dropdown `label`s in each section `_index.md` are translated. `user_groups` are translated to match `content/<lang>/home/people.md` (e.g. 博士課程学生 / 修士課程学生) for the four student groups; `Principal Investigators`/`Alumni *` stay English (People widget doesn't filter them).
- **Tutorial cards → English:** `layouts/partials/tutorial_card.html` honours an optional `card_url` front-matter key. Spanish/Japanese stubs set `card_url: "/tutorials/<slug>/"`, verbatim English `categories`, and `_build: {render: never, list: always}`. NEVER use the reserved `url:` key for this (it relocates the page and collides with the English URL). The homepage `tutorial-teaser` shortcode (`layouts/shortcodes/tutorial-teaser.html`) localizes its "browse all" label via a `dict` keyed on `site.Language.Lang` — add a language key there when introducing a new language.

## Interface text (not content) — where each string lives

English UI text on an ES/JA page is a bug. When you add UI text, add all three languages:

| Text | Source |
|---|---|
| Homepage copy, content-page footer (`footerTag`, `footerExplore`, `footerResources`, `footer`), copyright line on the homepage (`rights`) | `data/orbital.json` (keep `en`/`es`/`ja` in sync) |
| Copyright line on content pages | per-language `copyright:` in `config/_default/languages.yaml` |
| Theme strings (search modal, publication types, contact form, "posts", dates) | Wowchemy `i18n/*.yaml`, overridden by the project's `i18n/ja.yaml` / `i18n/es.yaml` where the theme left English |
| Catalog pages (Books/Software/Data/WebApps): filter labels, `tutorial_label`, `open_label` | each section `_index.md` (`filters:` `label`s; option `value`s stay English) |
| Tutorials gallery (search, chips, sort, empty state, news, topic names) | `ui:` and `topic_labels:` maps in `content/{es,ja}/tutorials/_index.md` (English is the template fallback) |
| Menu labels | `config/_default/menus.yaml` (EN) and `languages.yaml` (ES/JA); keep them short (see `design-system.md` §4) |

Dates in templates must use `time.Format` (localized), never `.Date.Format` (English month names).

**Linking from translated pages:** ES/JA tutorial stubs never render. Any `/es/` or `/ja/` page that points to a tutorial, including the WebApps tutorial buttons, must use the English `/tutorials/<slug>/` URL.

## Translate new content (REQUIRED) — per-section field treatment

Whenever qualifying content is added or materially edited under `content/<section>/<slug>/`, the SAME change MUST create/update its ES (`content/es/…`) and JA (`content/ja/…`) counterparts — there is no English fallback, so an untranslated item simply will not appear on `/es/` or `/ja/`.

Folder names differ from the Wowchemy content types they cascade: `articles/` pages are type `publication`, `presentations/` pages are type `event`, `tutorials/` pages are type `post` (set by `cascade` in each section `_index.md`).

- **`articles`, `presentations`, `books`, `software`, `data`, `webapps`, `authors` — full translation.** Translate `title`/`subtitle`/`abstract`/`summary`/`bio`/`role`/`interests`/`event`/`location`/`links[].name`/body prose + headings. Copy `featured.*`/`cite.bib`/`avatar.*` verbatim into the translated bundle. Keep `authors`/`date`/`doi`/`publication_types`/`tags`/`categories`/all URLs (incl. `app_url`)/`icon`/`icon_pack`/`image`/`_build`/`aliases`/filter params (`platform`/`region`/`topic`/`data_type`/`book_format`) byte-for-byte. Each section `_index.md` (with its `filters:` dropdown labels) also needs an ES/JA copy.
- **`tutorials` (type `post`) — stub card only.** `content/<lang>/tutorials/<slug>/index.md` with translated `title`+`summary`, verbatim English `categories`, `card_url: "/tutorials/<slug>/"`, `featured: false`, `_build: {render: never, list: always, publishResources: false}`, empty body — never the reserved `url:` key. Tutorials are the ONLY stub-card exception.
- **Standalone pages — full translation.** **courses** (`content/<lang>/courses/_index.md` + menu item), **alumni** (`content/<lang>/alumni/{index.md,people.md}` — keep the Alumni `user_groups` English; fix the `home/alumni-link.md` target to `/<lang>/alumni/`), **slides**, and the root **privacy/terms** pages. Field-level Translate-vs-Keep details in `.claude/skills/translate-content/references/field-rules.md`.

`scripts/i18n-parity.sh` tracks all sections (its header documents the flags; `--list` emits a TSV worklist; exits non-zero on gaps). `scripts/hooks/pre-commit` (enable via `git config core.hooksPath scripts/hooks`) reports gaps on commit.

## Geolocation

`netlify/edge-functions/geo-lang.ts` 302-redirects Spanish-speaking countries (Latin America + Spain + Equatorial Guinea) `/ → /es/` and Japan (`JP`) `/ → /ja/` — homepage only, fires once (`geo_seen`), respects the `lang_pref` cookie set by `assets/js/lang-pref.js` (bundled via `params.yaml` `plugins_js`; its `KNOWN` map is `{es, ja}`). `layouts/partials/custom_head.html` adds the `x-default` hreflang. Geo can only be tested on a Netlify deploy preview / `netlify dev`, not `hugo server`.

## Add another language (e.g. `ko`)

In `languages.yaml` add the block (code/name/weight and a localized copy of the full menu); in `config.yaml` add a `content/<lang>` mount, extend the en mount's `excludeFiles` to `'{es,ja,<lang>}/**'`, and (for CJK) keep `hasCJKLanguage: true`; add the country→`/<lang>/` line in `geo-lang.ts` + `<lang>` to its `KNOWN_LANGS`, and `<lang>: 1` in `lang-pref.js`; then `cp -R content/es content/<lang>` and translate each `.md` in place. No template/structural changes. **Hugo build needs ≥0.96** — verify with the pinned extended binary before pushing.

## Known minor issue

Thin ES/JA tutorial stubs republish the English bundle's small figure/script files under `/es/tutorials/<slug>/` (a few MB; harmless). Articles/presentations/books/software/data don't leak extra; WebApps bundles are `render: never` and publish only their `featured.jpg`.
